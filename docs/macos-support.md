# macOS Support: What It Would Take

Klip is Linux-only today. This document lists every place the code assumes Linux,
what macOS needs instead, and a suggested order of work. Nothing here has been
built or tested on a Mac yet; items marked **(verify)** are expectations that
need checking on real hardware.

## Summary

| Area | Linux today | macOS needs | Effort |
|---|---|---|---|
| Clipboard capture | Wayland data-control, Klipper D-Bus, X11 XFixes, polling (`klip/src/watcher/`) | Poll `NSPasteboard.changeCount` | Medium |
| Copy back | `wl-clipboard-rs`, `wl-copy`, `xclip` (`klip/src/ipc.rs`) | Write to `NSPasteboard` | Small |
| Tray | `ksni` (D-Bus StatusNotifierItem) | `NSStatusItem` menu bar extra | Medium |
| Global shortcut | User binds `klip` in DE settings | App registers its own hotkey | Medium |
| Single instance | `gtk4::Application` over D-Bus | No session bus; needs another mechanism | Small to medium |
| Daemon startup | `systemctl --user start klipd` | `launchd` LaunchAgent | Small |
| Start at login | `~/.config/autostart/klip.desktop` | LaunchAgent or `SMAppService` | Small |
| Paths | XDG dirs | `~/Library/Application Support/klip` | Small |
| Packaging | `.deb` / `.rpm` via cargo-deb / generate-rpm | `.app` bundle in a `.dmg`, signed and notarized | Large |
| GUI | GTK4 + libadwaita | GTK4 works on macOS, but has to be bundled and feels non-native | Decision needed (see below) |

The parts that carry over unchanged:
- `klip-common` types and the IPC protocol
- `storage.rs` (rusqlite with bundled SQLite)
- Unix-domain sockets (`std::os::unix::net`)
- `nucleo` search and the config file format

## 1. Make the workspace build on macOS

Several dependencies don't compile, or make no sense, off Linux. Gate them by target:

```toml
# klip/Cargo.toml
[target.'cfg(target_os = "linux")'.dependencies]
x11rb = { version = "0.13", features = ["xfixes"] }
wayland-client = "0.31"
wayland-protocols = { version = "0.32", features = ["client", "staging"] }
wayland-protocols-wlr = { version = "0.3", features = ["client"] }
wl-clipboard-rs = "0.9"

[target.'cfg(target_os = "macos")'.dependencies]
objc2 = "0.5"
objc2-app-kit = { version = "0.2", features = ["NSPasteboard"] }
objc2-foundation = "0.2"
```

```toml
# klip-gui/Cargo.toml
[target.'cfg(target_os = "linux")'.dependencies]
ksni = { version = "0.3.6", features = ["blocking"] }

[target.'cfg(target_os = "macos")'.dependencies]
tray-icon = "..."       # NSStatusItem
global-hotkey = "..."   # Carbon RegisterEventHotKey
```

The same gates go on the code:
- `klip/src/watcher/`: `mod wayland_dc; mod kde; mod x11; mod fallback;` become
  `#[cfg(target_os = "linux")]`, and a new `#[cfg(target_os = "macos")] mod macos;`
  is added.
- `start_watcher` and `detect_backend` pick the backend per OS.
- `ensure_xwayland_auth` is Linux-only.
- `copy_to_clipboard` in `ipc.rs` becomes a per-OS function.
- In `klip-gui`, `tray.rs` becomes a per-OS module behind the same small interface:
  spawn, update on events, and menu callbacks.

## 2. Daemon

### Clipboard watcher (`klip/src/watcher/macos.rs`)

macOS has no clipboard-change notification, so every clipboard manager on macOS
(Maccy included) polls `NSPasteboard.generalPasteboard.changeCount`. Reading that
integer is cheap, so polling every 250–500 ms is fine. This is not the lossy
5-second `wl-paste` poll from Linux. When the count changes:

1. **Skip private clips.** If `types` contains `org.nspasteboard.ConcealedType`,
   `org.nspasteboard.TransientType` or `org.nspasteboard.AutoGeneratedType`, drop
   the clip. Password managers (1Password, Bitwarden, Keychain) mark copied
   secrets this way, and storing them would be a privacy bug.
2. **Text:** if `public.utf8-plain-text` is offered, send `Clip::Text`.
3. **Images:** otherwise, if `public.png` is offered, send `Clip::Image` with
   `image/png`. Screenshots and many apps offer only `public.tiff`, which has to
   be converted to PNG first, because the GUI thumbnails and `images_dir` expect
   PNG/JPEG/WebP. `NSBitmapImageRep` can do that conversion.
4. **Files:** Finder copies arrive as `public.file-url`. Mapping them to
   `text/uri-list` or a path would be new behaviour; Linux doesn't capture file
   copies specially today.

AppKit pasteboard calls are safe from a background thread **(verify)**, so this
fits the existing watcher-thread → `mpsc<Clip>` design. The daemon doesn't need
an `NSApplication`.

**Self-capture:** when the daemon writes a clip back on `Copy`, `changeCount`
goes up and the watcher sees its own write. `Storage::insert` deduplicates, so
the result is a harmless `updated_at` bump, the same as on Linux.

### Copy back (`ipc.rs::copy_to_clipboard`)

Use `clearContents()` followed by `setData:forType:`, with
`public.utf8-plain-text` for text and `public.png` for images. Unlike Linux,
the clipboard keeps the data after the writer moves on, so no helper process
(`wl-copy`, `xclip`) is needed and none has to be waited on.

### Paths (`klip-common/src/lib.rs`)

`data_dir()` and `config_path()` read the XDG variables, falling back to
`~/.local/share` and `~/.config`. On macOS, use:

- data: `~/Library/Application Support/klip/`, which holds `klip.db` and `images/`
- config: `~/Library/Application Support/klip/config.toml`. `~/.config/klip` is
  also acceptable; many CLI-style tools use it.
- socket: **don't** put it under Application Support. macOS limits socket paths
  to 104 bytes (Linux allows 108), and that path contains a space and gets long.
  Use `$TMPDIR/klip.sock` instead: `$TMPDIR` is per user, so this is the closest
  equivalent to `XDG_RUNTIME_DIR`.

The default config that `klip-common` writes tells users to run
`systemctl --user restart klipd`. That line needs a macOS wording.

### Service (`klipd.service` → LaunchAgent)

Ship `~/Library/LaunchAgents/com.klip.klipd.plist` with `ProgramArguments`
pointing inside the app bundle, plus `RunAtLoad` and `KeepAlive`.

`ensure_daemon_running` in `klip-gui/src/main.rs` currently runs `systemctl`.
On macOS it would run `launchctl kickstart gui/$UID/com.klip.klipd`, or simply
spawn `klipd` from the bundle and skip launchd unless "Start at Login" is on.

**Simpler alternative:** on macOS, run the watcher, storage and IPC as threads
inside the GUI process, with no separate daemon. Every macOS clipboard manager
works this way, and it removes the LaunchAgent and the socket-discovery step.
The cost is that macOS and Linux would be structured differently.

## 3. GUI

### The main decision: keep GTK, or write a native front-end

**Option A: keep GTK4 (`klip-gui`).** GTK4 has a macOS (Quartz) backend.

- Pros: one GUI codebase, and the palette, search and row menu keep working.
- Cons:
  - The `.app` has to bundle GTK, GLib, Pango, Cairo, gdk-pixbuf, libadwaita and
    their dylibs, roughly 50–100 MB. Each dylib needs `install_name_tool`
    rewriting and signing; `gtk-mac-bundler` or a custom script can do it.
  - The window doesn't behave like a native macOS panel.
  - The GTK macOS backend gets less testing than the Linux ones.

**Option B: native SwiftUI/AppKit front-end.** It talks to `klipd` over the same
newline-JSON socket protocol (documented in `docs/CLAUDE.md`).

- Pros: a small app, a native look, and `NSPanel` with
  `.nonactivatingPanel`, which is exactly the behaviour a clipboard popup wants.
- Cons: the UI would be written twice, in Rust/GTK and Swift.

**Recommendation:** start with **A** to get a working build quickly, since every
item in sections 1, 2 and 4 is needed for both options. Move to **B** only if
the GTK look or the bundle size becomes the main complaint. The IPC boundary
already makes that swap cheap.

### Changes needed if GTK stays

- **Single instance.** `gtk4::Application` uniqueness works over D-Bus, and macOS
  has no session bus, so a second `klip` launch would open a second app
  **(verify)**. On macOS this matters less: the hotkey lives *inside* the running
  app (next item), so `klip` is launched once at login and never relaunched.
  Use `ApplicationFlags::NON_UNIQUE` there, or a lock file.
- **Global hotkey.** On Linux, users bind `klip` in their DE settings. macOS has
  no such setting for arbitrary commands, so the app has to register the hotkey
  itself, for example with the `global-hotkey` crate (Carbon
  `RegisterEventHotKey`, which needs no Accessibility permission), and call
  `activate` when it fires. It needs a configurable key (a new config key such as
  `hotkey = "cmd+shift+v"`), and Cmd+Shift+V is the usual default.
- **Tray.** Replace `ksni` with `tray-icon`, which provides `NSStatusItem`
  menus. `tray.rs`'s menu model (recent clips, pause, clear, start at login,
  quit) carries over.
  - Icon names resolved from the icon theme (`tray::Icons::resolve`) don't exist
    on macOS. Use SF Symbols, or bundled template PNGs: monochrome images that
    macOS tints for light and dark menu bars.
  - The KDE workarounds (`relayout`, `__` mnemonic escaping, avoiding checkmark
    items) are DBusMenu-specific. Native checkmark items are fine on macOS.
  - `tray-icon` needs the main thread's run loop. GTK's macOS backend runs the
    NSApplication loop, so creating the tray on the GTK main thread should work
    **(verify)**.
- **No Dock icon.** Call `NSApp.setActivationPolicy(.accessory)` at startup
  through `objc2`, or set `LSUIElement = true` in `Info.plist`. Either way the
  app lives only in the menu bar.
- **Showing the palette.**
  - Undecorated windows work. Positioning near the cursor, staying on top and
    appearing on the current Space and over full-screen apps require
    `NSWindow` settings (`level`, `collectionBehavior`) through objc on the
    native handle; GTK has no API for them.
  - The palette should open without making Klip the active app. Otherwise the
    previously focused app loses focus, which also blocks a future
    paste-into-app feature.
- **Auto-close on focus loss.** The palette closes when
  `gdk::ToplevelState::FOCUSED` is cleared, a change made for KWin
  (see `docs/CLAUDE.md`). Check that the Quartz backend reports this state;
  if it doesn't, fall back to `is_active` on macOS **(verify)**.
- **Shortcuts.** The palette uses Alt+1–9, Alt+P, Alt+Delete and Ctrl+Backspace.
  On macOS users expect Cmd+1–9, Cmd+P (or Cmd+D), Cmd+Delete and Cmd+Shift+Delete.
  Map these by checking `ModifierType::META_MASK` on macOS, and update the hint
  labels in `row_menu.rs` and the footer.
- **CSS.** `style.css` uses fonts by family name. Check that they resolve on
  macOS; otherwise add `-apple-system` / `SF Pro`.
- **Start at Login** (`tray.rs::set_autostart`). Writing
  `~/.config/autostart/klip.desktop` does nothing on macOS. Use `SMAppService`
  (macOS 13+) for the GUI, or a LaunchAgent plist.
- **Open Link.** `gio::AppInfo::launch_default_for_uri` should map to
  `NSWorkspace` through GIO's macOS backend **(verify)**. `open <url>` is a safe
  fallback.

## 4. Packaging and distribution

- **Bundle layout:**
  ```
  Klip.app/Contents/
    Info.plist          (CFBundleIdentifier com.klip.clipboard-manager, LSUIElement)
    MacOS/klip, klipd
    Resources/klip.icns (built from icons/klip.svg with iconutil)
    Frameworks/         (GTK dylibs, Option A only)
  ```
  `cargo-bundle` produces the basics. The GTK dylib bundling needs a script.
- **Universal binary:** build `aarch64-apple-darwin` and `x86_64-apple-darwin`
  and merge them with `lipo`, or ship Apple Silicon only.
- **Signing and notarization:** without them, Gatekeeper blocks the app
  ("damaged" or "unidentified developer"). Requirements:
  - an Apple Developer ID ($99/yr)
  - `codesign --options runtime` on every binary and dylib
  - `notarytool submit` and `stapler staple`
  - Unsigned builds still work for testing (right-click → Open, or
    `xattr -dr com.apple.quarantine Klip.app`).
- **Distribution:** a `.dmg` (via `create-dmg`) attached to the GitHub release,
  plus a Homebrew cask, which is how most Mac users install tools like this.
- **CI:** add a `build-macos` job on `macos-14` (Apple Silicon) to
  `.github/workflows/package.yml`. For Option A it runs
  `brew install gtk4 libadwaita`. Signing secrets (certificate p12 and
  notarization API key) go in repository secrets.
- **Version:** read it from the workspace `Cargo.toml` into `Info.plist`
  (`CFBundleShortVersionString`).

## 5. Permissions

- **Reading and writing the pasteboard:** no permission needed. macOS 15.4+ adds
  a user-facing prompt when an app reads the pasteboard *programmatically*
  without user interaction **(verify)**. Clipboard managers are the main case it
  targets, so check how Maccy handles it at implementation time.
- **Global hotkey via Carbon:** no permission needed.
- **Paste into the previous app** (a future feature): needs **Accessibility**
  permission to post a synthetic Cmd+V with `CGEventPost`. It's the same feature
  that's missing on Linux today.

## Suggested order of work

1. Gate the Linux-only dependencies and modules so `cargo build` succeeds on macOS.
2. Add per-OS paths in `klip-common` (data dir, config, `$TMPDIR` socket).
3. Add the pasteboard watcher and copy-back in `klipd`. Test with the Python IPC
   snippet from `docs/CLAUDE.md`.
4. Run the GTK GUI from a terminal: check the palette, search, copy and the row menu.
5. Add the in-app global hotkey and `NON_UNIQUE`.
6. Add the `tray-icon` menu bar extra and `LSUIElement`.
7. Add Start at Login and the daemon launch (LaunchAgent, or the in-process
   alternative).
8. Bundle, sign and notarize, then add the CI job and the `.dmg`/Homebrew cask.

Steps 1–3 are worth doing even if Option B is chosen later, because the native
front-end would use the same daemon.
